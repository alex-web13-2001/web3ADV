================================================================================
API ENDPOINTS:
================================================================================

Backend Server (http://localhost:3001)

Public:
  GET /api/health
    → Health check, returns server status

Authenticated (requires X-API-Key header):
  GET /api/campaigns
    → Get campaign count from WB API
    
  GET /api/campaigns/list
    → Get list of all campaigns
    
  POST /api/campaigns/fullstats
    Body: { id: [campaignId], dates: { from, to } }
    → Get detailed campaign statistics
    
  POST /api/clusters/stats
    Body: { id: [campaignId], dates: { from, to } }
    → Get search cluster statistics

================================================================================
DATA FLOW:
================================================================================

1. User enters Wildberries API key in frontend
2. Frontend sends API key to backend via X-API-Key header
3. Backend validates key and proxies request to Wildberries API
4. Wildberries API responds with campaign data
5. Backend forwards response to frontend
6. Frontend displays data in charts and tables

No data is stored locally - all requests are live to Wildberries API.

SUPPORT & TROUBLESHOOTING:

   → Check firewall settings
   → Verify API key is valid

   → Check date range
   → Verify campaign has data
   → Check browser console for errors
